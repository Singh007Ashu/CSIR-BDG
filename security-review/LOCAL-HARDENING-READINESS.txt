CSIR BDG local security hardening update - 6 November 2026

CHANGES
1. Python worker JSON parsing is caught and rejected safely instead of throwing
   from an asynchronous close handler. Every completion/error path clears the
   timer. Stdin errors, spawn failures and nonzero exits are handled.
2. Worker stdout is capped at 2 MB, stderr at 64 KB, with timeout termination.
   No shell is used. Existing matching fallback behaviour is preserved.
3. Upload validator rejects unknown types even when invoked directly.
4. Archives reject nested archives, active content, embedded Office objects,
   unsafe filenames and external Office resource relationships. Ordinary
   hyperlinks remain allowed. Office XML DTD/entity declarations are rejected.
5. Actual inflated entry bytes are checked before downstream parsing: 10 MB
   per entry, 50 MB total, in addition to the existing archive metadata limits
   and 5 MB compressed upload limit.

COMPATIBILITY
New files containing the rejected archive/Office constructs must be converted
to plain supported documents before upload. Existing files are not rewritten,
deleted or bulk-scanned. Legacy DOC/XLS/PPT deep parsing is not certified.
Worker limits are resource guards, not an OS-level parser sandbox.
